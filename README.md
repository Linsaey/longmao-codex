# 龙猫放置 · 图鉴（单页版）

游戏《龙猫放置》的离线图鉴。一个 HTML 页面 + 一份数据文件 + 一批压缩图标，纯前端无依赖，
手机浏览器和电脑浏览器都能直接打开。

## 印章（拓印）

2026.11.15 版本新增的拓印系统单独成栏，数据取自 `imprint_normal.json` / `imprint_special.json`，
出现率按客户端 `Vp()` 权重抽取逻辑复算（祥瑞 / 凶煞为对应组权重 ×1.5，乾坤把普通词条权重清零）。

- 普通词条 16 条：一阶~五阶都有，每条权重 100，双值词条（固定值 + 百分比）与纯百分比词条分开列。
- 特殊词条 9 条：圣兽 5 条（朱雀 / 青龙 / 白虎 / 玄武 / 麒麟）、凶兽 4 条（饕餮 / 穷奇 / 梼杌 / 混沌），仅三阶及以上。
- 特殊总出现率：无特殊印章 T3 3.50% / T4 10.21% / T5 16.23%；祥瑞 4.93% / 13.84% / 21.38%；
  凶煞 3.73% / 11.01% / 17.53%；乾坤 100%（一、二阶无特殊池，实际不可用）。
- 普通词条单条出率：6.25%（无特殊）→ 6.03% / 5.61% / 5.24%（T3 / T4 / T5 带特殊印章时）。

「分解装备到底给几阶几个印章」由服务器结算，客户端静态表（`refine.json` / `drops.json` / `shop.json` / `craft.json`）里没有，故图鉴未列出。

## 掉落概率口径

数据来自游戏本体静态表 `/data/drops.json`，概率按客户端 `Nv()` 的结算逻辑复算：

- `rollMode = independent`：逐条独立判定，概率即 `chance`。
- `rollMode = group_pick_1`：按 `pool` 分组，**整池概率 = 池内首行的 `chance`**，
  命中后池内等概率随机取一条 → **单件真实概率 = 池概率 / 池内件数**。

因此怪物详情里同一装备池内的每件装备概率相同（如 10% / 23 件 ≈ 0.435%）。
单件概率低于 0.05% 的池不在明细里逐条列出，只在「其它池」里给出整池概率与件数。

## 目录

```
index.html        页面（结构 + 样式）
app.js            渲染逻辑（分类、搜索、筛选、详情弹层）
data.js           打包后的游戏数据（window.CODEX = {...}）
img/              914 张压缩图标（怪物 96px JPEG，物品/技能 56px WEBP）
build_codex.py    从游戏静态表重新生成 data.js 与 img/ 的构建脚本
```

## 本地打开

直接用浏览器打开 `index.html` 即可（`data.js` 与 `img/` 需在同一目录）。

## 重新生成数据

```bash
python build_codex.py
```

脚本默认从 `C:\Temp\g5data\*.json`（游戏静态表本地副本，可用环境变量 `CODEX_DATA`
换成别的目录）与 `C:\Temp\imgcache`（图标原始缓存，路径索引 `C:\Temp\imgindex.json`）
读取，重新压缩图标并输出 `data.js`。原始表用
`http://106.14.162.38:8080/data/<表名>.json` 抓取（旧地址 `43.142.100.84:8080`
目前与它是同一套构建/同一份数据）；图标用同一域名拼上表里的 `image` 字段下载。
`buffs.json` 服务端已不再提供（返回的是 404 HTML 页），但药水 BUFF 是从 `items.json`
里 `potionType=buff` 推导的，不影响构建。
